# OMG AD · Windows 技能征召助手原型

本地截图识别 + 动态增益 Top 10 + 鼠标穿透透明覆盖层。适配用户提供的标准技能征召参考布局，支持手动校准；不修改游戏文件，不读游戏内存，也不会替你点击选技能。

## 运行

直接双击项目根目录的 **OMG AD.exe**。这是自带运行时的 Windows 图形程序，不显示命令行窗口，也不需要单独启动 `dotnet`。首次打开可能需要数秒解压运行组件；请保留同目录的 `data` 文件夹。`Start-OMGAD.cmd` 只作为兼容入口，最终也会启动同一个独立程序。

启动脚本默认打开控制台；设置位置后点击“连接 Dota 2”。程序已在后台时，再双击启动脚本或 EXE 会唤出已有控制台，不会静默退出。F10 也可返回控制台。

1. 先设置“我的位置”（会自动保存），“查看推荐”可以切换到任一玩家，不会修改“我的位置”；“编辑位置”用于手工录入选择。技能框和双方阵容估算随双方选择更新，前三名另有文字摘要。
2. 用“导入截图”打开一张自己的选技截图，查看识别与高亮。已叠有其他助手文字的图片会降低识别率。
3. 在“校准识别格”中选择左侧格子，在右侧拖选对应图标内部。保存后生效。默认坐标来自提供的参考截图；不同布局或宽高比需要重新校准。两侧玩家的 hero-name 区域只框 ID 上方的英雄名字，不要框玩家 ID；pick 区域框技能图标。
4. Dota 2 使用**无边框窗口**，每局点“新的一局”，设置自己的位置，再点“连接 Dota 2”。切回游戏后每约 1.2～3 秒识别一次（取决于截图大小及 OCR 耗时）；连续两帧一致才更新。
5. **F8** 覆盖层显隐；**F9** 暂停/继续识别（保留已显示结果）；**F10** 返回控制台。游戏前台时覆盖层常驻，识别失败只更新提示，切走游戏才自动隐藏。退出控制台即可退出程序。

0.1.1 修复了截图前隐藏窗口导致的周期性闪烁。现在用 Windows 的 [SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity) 把覆盖层从截图中排除，无须隐藏再显示。若系统不支持截图排除，则暂停识别并保留结果。增加单实例限制，重复启动不再叠加多个覆盖层。

0.3 将**英雄和技能一起排名**：每手模拟给“查看推荐”位置选一个英雄或一个技能，以该阵营选后估算增益排序，只显示正增益，最多 10 项。已有英雄的位置不再推荐英雄；选择英雄不会自动获得其技能。标注 `+1.20pp` 代表增加 1.20 个百分点，例如 50% → 51.20%。影魔、莉娜等英雄的本体统计已参与首手排序。

颜色规则：第 1 名红色柔光，第 2 名橙色，第 3–4 名紫色，第 5–7 名蓝色，第 8–10 名绿色；数字 01–10 给出准确顺序。0.4 的彩虹外框独立于前 10 名排名：所有当前合法、命中已知组合的候选都可显示，前十之外不显示排名数字和增益。“联动”代表搭档已被自己选中，“可追”代表搭档仍在池中且后续槽位允许；可追不是已经完成的组合。“适配”表示远程 / 敏捷本体与攻击特效的通用规则，不是专属技能触发。英雄与技能可双向提示；大招区域左右空白处显示具体搭档，不再覆盖聊天区。框内是当前查看位置所属阵营的增益，顶部是当前双方估算值和上一手变化，控制台前三张卡显示候选选下后的双方估算值。

柔光采用 [UpdateLayeredWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-updatelayeredwindow) 的逐像素透明合成，静态发光，不使用明暗闪烁。截图和计算期间保持窗口及上一次结果，完成后一次更新。

识别不准时可以在下拉框搜索中文技能/英雄名，手动选取；“加到技能池”会保留人工补充项；点击池内图标可排除误识别。清空位置、恢复禁用、撤销可纠正录入。标准技能征召的不可选项按已选/排除处理；没有假设一个额外 ban 轮次。

0.4.1 修复英雄槽识别状态：已选英雄后锁定该位置，不会因 OCR 失败或旧的“无英雄”文字重新推荐第二个英雄。未识别清楚时暂停英雄推荐，技能推荐继续；确认“无英雄”后才允许首个英雄推荐。切换查看其他位置分别计算。识别到单个英雄时不再依赖池内至少 6 个图标才提交。联动文字移动到大招左右空白区域。

0.4.2 统一可选性检查，优先级高于所有联动分数。当前候选必须仍可选；后续搭档必须在选下当前候选后仍满足英雄 / 技能槽限制。已选走或暗掉的卡牌即时退出推荐，旧排名和联动文字缓存显示前再次过滤；手工补池不能覆盖随后识别到的不可选状态。已确认英雄不会被后续 OCR 换成另一英雄。联动面板明确区分“选：当前可选项”和“配合已选 / 后续可选：搭档”。

## 点击切换与备用快捷键

连接 Dota 2 后，直接左键点击两侧玩家的头像或名字 / ID 区域即可查看该位置的推荐，蓝框标出当前查看位置；点击自己的卡片即可返回。覆盖层不会抢焦点或吞掉鼠标点击，原游戏点击行为仍保留。点击已选技能图标不会切换视角。控制台和截图预览也支持点击玩家卡片。

顶部栏整体上移 60 个设计像素，为中央倒计时留出空间。以下热键保留为备用：

- Ctrl+Alt+1 / 2 / 3 / 4 / 5：查看天辉 1 / 2 / 3 / 4 / 5。
- Ctrl+Alt+6 / 7 / 8 / 9 / 0：查看夜魇 1 / 2 / 3 / 4 / 5。
- Ctrl+Alt+M：回到保存的“我的位置”。使用主键盘数字键。

快捷键只改变查看推荐的位置；双方阵容与我的位置保持。游戏前台可以切换，无须先打开控制台。

## 已实现

- 513 技能 / 127 英雄的本地图片与中文 ID 映射。
- 玩家英雄身份读取 ID 上方的中文英雄名：使用本机 Windows 中文 OCR，文字无法确认时保留未知；不再匹配两侧的竖版肖像。需要系统安装简体中文 OCR 语言包。
- 屏幕图标模板匹配：局部位移/缩放搜索、置信度阈值、候选差距、重复检测、连续帧确认。模糊图标留空。
- 10 个位置的英雄/技能状态；1 英雄 + 3 普通技能 + 1 大招约束、全局不可重复、互斥技能过滤。
- 每次状态变化重新试算正增益 Top 10；由当前英雄、已选技能和双方阵容估算得出，带可用组合提示。原推荐分仅作相同增益时的排序依据。
- 独立 Windows 透明置顶窗口，鼠标穿透，不抢游戏焦点；覆盖 Top 10 数字和彩色柔光框，顶部保留前三名摘要，实时显示双方阵容估算。
- 原始截图预览、逐格校准、手工纠错、演示模式、推荐理由、阵容估算走势。

## 数据来源与诚实边界

`data/statistics.json` 现包含 513 个技能、126 个英雄、6813 组二元组合和 9870 组三元组合。随程序附带的完整快照来自 Ability Draft Plus 的公开离线数据库（ISC，上游为 Windrun.io，抓取时间 2026-07-31）。控制台的“更新完整统计”会低频调用 Windrun API v2，成功后原子替换并立即生效；失败时保留旧库。Windrun 若返回 Cloudflare 验证页，程序不会尝试绕过。

推荐依据由三部分组成：

- 单技能胜率和样本数：参考网站转载的 Windrun 数值，按 `n/(n+1000)` 收缩到中性基线。
- Windrun 本身有 [Ability Pairs 组合统计](https://api.windrun.io/ability-pairs)。当前接口读取返回 403，本程序尚未接入完整组合库，不能说是 Windrun 不支持。
- 技能组合：当前**没有实证组合统计**；使用源码中公开列出的 10 条启发式规则。规则可能随版本变化，分数不是胜率百分点。
- 英雄适配、未来可组合项和阻断对方组合：轻量规则。76 个英雄本体胜率收录在 `data/hero-statistics.json`，来自 [Windrun 英雄页面](https://api.windrun.io/ability-by-hero) 搜索缓存中明确标为 body winrate 的数值。版本、样本数和统计时间窗未知，不当作最新版本数据；缺失英雄保持中性。只有合法且池中仍存在的技能计入组合机会。

“双方胜率”是 `sigmoid((天辉强度−夜魇强度)/65)` 的**未经校准估算**，不是 Windrun 给这局的胜率，也不是经过比赛结果验证的预测模型。未知选项贡献为零；目前无法建模阵容控制链、玩家水平、装备、分路、完整克制关系。排除技能改变后续推荐，但不会凭空给已确定阵容增加胜率。

截图默认有 60 个池内识别格，包含英雄牌和技能牌。两侧未知英雄/空技能格保持未知。当前不会自动判断轮到谁，也不会自动判断新的一局；须设置自己的位置并每局重置。已经记录的选取保持到人工纠正/重置；已增加暗牌排除，剩余池不足 6 项时仍可通过已选英雄/技能更新阵容；遮挡或选中动画仍可能影响识别。实时游戏、不同分辨率/DPI、独占全屏尚未经过实机对局验证。

## 构建与验证

无需第三方 NuGet 包。需要 Windows + .NET 10 SDK。

```powershell
dotnet restore --configfile NuGet.Config -p:NuGetAudit=false
dotnet build -c Release --no-restore
Start-Process -FilePath .\bin\Release\net10.0-windows\OMGAD.exe -ArgumentList '--self-test --image .\research\reference-draft.png --late-image .\research\late-draft.jpg --out .\artifacts' -WindowStyle Hidden -Wait
Get-Content artifacts/test-results.txt
```

验证覆盖合法选取、互斥和唯一性、状态驱动重排、缺数据处理、阵营对称性、模板识别、两帧稳定提交、空白帧保留状态。输出控制台渲染预览、带覆盖标记的参考截图、逐格识别 JSON 与测试日志。参考截图中的“接受识别数量”不是经过逐项标注的准确率，也不代表实机测试通过。

0.2 还验证了 Top 10 正增益过滤、阵营方向、模拟选取不修改真实状态、预测与实际选取后数值相等、已选/可追组合过滤，以及实际透明窗口重绘不改变可见性、逐像素合成成功。`combo-overlay-preview.png` 是明确标记“假设已选余震”的样式演示，不是识别到的实战状态。

0.3 新增真实后半程截图回归：检查两侧 10 个英雄名、每个位置 4 个已选技能、暗牌过滤及英雄/技能混选合法性。控制台演示包含英雄进入前三名的示例。截图识别通过不代表已完成实机对局验证。

## 更新数据

优先在控制台点击“更新完整统计”。它依次读取静态映射、技能/英雄、二元组合和三元组合，接口之间留出间隔并处理 429/503 重试。只下载公开统计，不上传截图、对局或用户数据。网站不可用时保留现有数据。

若取得授权的 Windrun 导出，可转成下列规范后用 `node tools/import-statistics.mjs 文件.json` 导入。不得填写猜测数值，`synergyPp` 是数据源明确提供的组合协同百分点，不能用组合胜率代替。导入成功后重新编译并重启。

```json
{
  "source": "真实数据来源 URL",
  "attribution": "统计范围、时间窗及来源说明",
  "fetchedAt": "ISO 8601 获取时间",
  "patch": "实际补丁版本，未知则写未知",
  "abilities": {
    "技能内部代码": {"winRate": 0.5, "samples": 1000, "avgPick": 20, "ultimate": false}
  },
  "heroes": {},
  "exclusive": [],
  "pairs": []
}
```

上方数值仅展示文件格式，不作为生产统计。组合数组支持技能 + 技能或英雄 + 技能，不接受双英雄组合。组合数组条目格式为 `{a,b,synergyPp,samples,source}`。至少 100 样本、有来源的配对会覆盖对应启发式规则，评分另加样本收缩。恢复镜像快照会替换手工导入数据，更新前请自行备份。

## 文件

- `src/MainForm.cs`：控制台和实时识别循环。
- `src/Vision.cs`：识别、稳定状态提交。
- `src/Engine.cs`：合法选项、推荐评分和估算。
- `src/Drawing.cs`：控制台渲染、透明覆盖层。
- `src/Calibration.cs`：图标区域校准。
- `data/`：本地素材、元数据、统计；图片由用户提供，未重新授权公开分发。

原型以“先试用与校准”为目标。要做可信的实时胜率产品，还需接入明确版本/时间窗的组合与英雄统计，并使用完整历史对局进行独立验证和概率校准。
